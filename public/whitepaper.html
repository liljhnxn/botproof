1. Abstract

Traditional digital credential verification relies on centralized databases, fragmented third-party verification portals, and manual background checks prone to tampering, single points of failure, and downtime. Concurrently, attempting to put sensitive identity documents on public blockchains violates fundamental data privacy principles (e.g., GDPR, CCPA) by making personal identifiable information (PII) permanent and public.

BotProof solves this dilemma by introducing a zero-knowledge, client-side cryptographic anchoring protocol deployed on BotChain Mainnet. Using the browser's native Web Crypto API, sensitive documents (academic diplomas, certificates, contracts, hackathon credentials) are hashed locally into an unalterable 32-byte SHA-256 digest. Only this mathematical fingerprint—never the document itself—is anchored to the Botchain smart contract.

Core Guarantee: Mathematical certainty of document integrity and issuer provenance without ever transmitting or storing confidential files outside the user's local device. Anyone with a proof ID or the original file can verify authenticity in seconds without connecting a Web3 wallet or paying gas fees.

3. Protocol Architecture

BotProof is structured into three decoupled layers to guarantee maximum security, speed, and privacy:

  1. Client Cryptographic Engine (Browser): Executes SHA-256 digests in-memory via window.crypto.subtle.digest. Operates asynchronously on arbitrary binary file streams (PDF, PNG, JPG, JSON) without server round-trips.
  2. Botchain Smart Contract Layer (BotProof.sol): Maintains the state registry of proofs, issuer permissions, holder indexes, revocation statuses, and timestamps on Botchain (Chain ID: 677).
  3. Public Verification Gateway: Provides instant dual-mode verification:
    • Proof ID lookup: Reads on-chain state, issuer address, issuance timestamp, and revocation flag.
    • Document Parity Check: Verifiers upload their copy of the file; client calculates hash and executes byte-for-byte cryptographic equality against the blockchain record.

4. Client-Side Cryptography & Privacy

To ensure pre-image resistance and complete data confidentiality, BotProof never transmits raw bytes across the network. The hashing procedure is executed directly on the client:

// Client-Side Web Crypto API Hashing async function generateDocumentHash(file: File): Promise<string> { const arrayBuffer = await file.arrayBuffer(); const hashBuffer = await window.crypto.subtle.digest("SHA-256", arrayBuffer); const hashArray = Array.from(new Uint8Array(hashBuffer)); return "0x" + hashArray.map(b => b.toString(16).padStart(2, "0")).join(""); }

Because SHA-256 is a one-way collision-resistant hash function, observing the 32-byte string on the Botchain public ledger reveals zero information about the student's name, grades, or personal identifiers contained in the document.

The core smart contract BotProof.sol is deployed at 0xc16BEc2A8068a3a4fc387b9e9c07459E90342C0B on BotChain Mainnet. It is written in Solidity 0.8.24 with strict access control and gas-efficient storage slots.

Custom Errors & Safety Checks

  • ZeroAddress(): Prevents minting credentials to address(0).
  • ZeroHash(): Prevents registering blank or unhashed documents.
  • NotIssuer(): Enforces that only the original issuing key can revoke an active proof.
  • AlreadyRevoked(): Guarantees idempotency and protects audit log sanity.

6. Verification Workflows

BotProof prioritizes zero barrier-to-entry for verifiers (employers, universities, compliance officers):

1. By Proof ID

Verifiers query the unique sequence identifier. The system retrieves issuer authenticity, timestamp, and status directly via Botchain RPC.

2. Document Drag & Drop

Verifier drops the PDF into the browser. The client hashes it and compares it against the smart contract record. If 1 byte differs, verification fails.

3. Direct Link & QR Code

Holders receive a shareable /verify/[id] URL and dynamic QR badge for inclusion on resumes, LinkedIn, and portfolios.

7. Security & Privacy Model

  • Zero PII Exposure: No names, IDs, social security numbers, or grade transcripts are stored on-chain.
  • Non-Custodial Architecture: BotProof never retains user private keys or file backups. Users maintain sovereign ownership of credentials.
  • Pre-image & Second Pre-image Resistance: SHA-256 ensures an attacker cannot craft a forged document with the same hash.
  • Permanent Audit Log: Once a proof is revoked, the event is permanently recorded on Botchain, preventing revoked certificates from ever passing verification.
